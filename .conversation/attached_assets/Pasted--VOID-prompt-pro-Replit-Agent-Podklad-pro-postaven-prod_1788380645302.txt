## Proč zrovna VOID (shrnutí researche)

Dnešní agentní stack má observabilitu (tracing, evaly), guardrails (filtrace vstupu
a výstupu) a schvalování člověkem. Co v něm chybí jako samostatná vrstva: možnost
**vrátit zpět to, co agent už reálně udělal** ve světě, tedy v CRM, e-mailu,
platbách, databázi, infrastruktuře. Rollback existuje jako návrhový vzor uvnitř
jednotlivých frameworků (saga pattern, kompenzační transakce), a jako marketingová
vlastnost uvnitř uzavřených platforem. Neexistuje jako nezávislá, systémově
agnostická vrstva mezi libovolným agentem a libovolným nástrojem, s kryptograficky
podepsaným logem, který zároveň plní záznamovou povinnost podle článku 12 AI Actu
(vymahatelný od srpna 2026).

To je díra na trhu, která je zároveň skvěle vizualizovatelná: časová osa akcí,
posuvník, a systémy se před očima vracejí do původního stavu.

Náhradní názvy, pokud by VOID kolidoval: REVOK, ANNUL, SAGA, VETO.

## 1. THE PRODUCT

**VOID, the reversible autonomy layer for AI agents.**

Positioning line: *Every action your agents take, reversible.*
Secondary line: *Ctrl+Z for autonomous systems.*

### The problem

AI agents no longer just answer. They write to CRMs, issue refunds, send email,
delete files, change infrastructure. The current safety stack watches (tracing),
filters (guardrails) and asks (human approval). None of it can **undo**. Once an
agent has acted, the damage is a manual cleanup ticket, and the audit trail is a
pile of unsigned JSON logs nobody can defend in front of a regulator.

### The product

VOID sits between any agent and any tool, as an MCP proxy or an SDK wrapper, and
turns agent side effects into reversible, provable transactions.

Six core mechanisms, these are the six feature cells on the site:

1. **Interceptor**
   Drop in front of any tool surface: MCP servers, HTTP tools, function calling,
   your own SDK. One line of config. Framework agnostic: LangGraph, CrewAI,
   OpenAI Agents SDK, Claude Agent SDK, custom loops.

2. **Preflight**
   Before a call commits, VOID computes its blast radius: which systems change,
   how many records, which fields, and the reversibility class. Policy decides:
   allow, require approval, or veto. Veto happens before the write, not after.

3. **Compensation compiler**
   For every intercepted call, VOID synthesizes the inverse action and captures a
   before snapshot. Create becomes delete. Field update becomes field restore.
   Meeting booked becomes meeting cancelled with a notice. Commit becomes revert.
   Object overwritten becomes object version restored.

4. **Saga ledger**
   An append only, hash chained, signed record of intent, payload, result,
   snapshot and compensation plan for every action. This is the undo stack and the
   compliance record in one. Exportable as an AI Act Article 12 style log.

5. **Time scrubber**
   Pick a moment. VOID replays compensations in LIFO order across every connected
   system and shows you, live, what came back and what did not.

6. **Irreversibility budget**
   Each agent gets a daily allowance of irreversible action. Spend it and the agent
   drops to read only until a human tops it up. Autonomy becomes a metered
   resource instead of a binary switch.

### Reversibility classes (a core visual on the site)

```
R0  fully reversible      snapshot restore, exact prior state    green
R1  reversible with trace  undone, but the change was visible     blue
R2  mitigable only         cannot unsend, can retract and notify  amber
R3  irreversible           money moved, data destroyed, no path   red
```

The pitch: *VOID does not promise everything is undoable. It promises you know
which class you are in before the agent acts, and that R3 costs budget.*

### Who it is for

Platform and infrastructure teams running agents in production, in fintech,
health, e-commerce operations and internal automation, plus the compliance people
who have to sign off on it.

## 3. VISUAL SYSTEM

The site copies the structural language of a "design tool utility landing":
a narrow centered frame with visible hairline rules, a serif display face against
a technical sans, and monospace annotation everywhere. Then everything decorative
is redrawn in ASCII.

### 3.1 Tokens

```css
:root {
  --bg:          #f7f8fb;
  --panel:       #f0f2f7;
  --line:        #e7e9f0;
  --line-strong: #d9dce6;
  --ink:         #000000;
  --gray-1:      #333333;
  --gray-2:      #545454;
  --gray-3:      #63666e;
  --gray-4:      #686c79;
  --accent:      #3455fa;   /* the only color, used sparingly */
  --accent-dark: #2040e3;
  --ok:          #1a7f5a;   /* R0 */
  --warn:        #a86a12;   /* R2 */
  --bad:         #b3261e;   /* R3 */
  --max:         1180px;
  --cell:        14px;      /* the ASCII grid unit, everything snaps to it */
  --ease:        cubic-bezier(0.16, 1, 0.3, 1);
}
```

Dark theme (`[data-theme="dark"]`, the "CRT" mode): `--bg: #07090d`,
`--panel: #0d1017`, `--line: #1b2029`, `--ink: #d7e2d9`, accent `#5f7dff`, plus a
very subtle scanline overlay at 3% opacity and a 0.4px text glow on monospace.
Both themes must be fully defined, no color may exist only inside a media query.

### 3.2 Type

- Display: **Instrument Serif** 400, `clamp(46px, 6.8vw, 74px)`, line height 1.06,
  letter spacing -0.01em. Used for h1 and h2 only.
- Text: **Inter** 400 and 500, base 15px, line height 1.6, letter spacing 0.01em.
- Mono: **JetBrains Mono** 400 and 500, used for every label, chip, code block,
  annotation, number, diagram and the entire ASCII layer.
- Kicker style above every section heading: mono, 11px, uppercase, letter spacing
  0.2em, color `--gray-3`, prefixed with a bracketed index, for example
  `[ 04 ] COMPENSATION`.

### 3.3 Frame and rules

- `main` is `max-width: var(--max)`, centered, with a 1px left and right border in
  `--line`. Every section has a 1px bottom border. This creates the spec sheet grid.
- At every intersection of those rules, render a small `+` crosshair in mono,
  9px, color `--gray-3`. Four of them per section corner set.
- Cards and figures get **crop marks**: four L shaped corner ticks, 1px, 9px long,
  offset 5px outside the box.
- Every figure carries a caption in mono 11px in the bottom left of its box:
  `fig. 03, compensation replay`.
- Section index in the top right corner of the viewport, fixed, mono 11px:
  `07 / 17  PRICING`, updated by an IntersectionObserver, hidden on mobile.
- A 2px scroll progress bar pinned to the very top, color `--accent`.

### 3.4 The ASCII layer

Build these as reusable client components in `components/ascii/`.

**`<AsciiField />`** the page background.
Full viewport fixed canvas at `z-index: -1`, drawn once and on resize only, no
requestAnimationFrame loop. Deterministic hash noise per cell so the pattern is
stable between redraws. Cell size 14px. Three character sets:

```
LIGHT  · . : ˙ , ; ° ' ^ ~ - _        most cells, alpha 0.06 to 0.20
MID    + * = < > / \ | [ ] { } ( ) !  about 15 percent, alpha 0.07 to 0.21
HEAVY  ░ ▒ ▚ ▞ # % & 0                about 5 percent, drawn in --accent
```

Density is weighted by distance to the nearest viewport edge: roughly 0.55 at the
edges falling to 0.16 in the center, so the reading column stays calm and the page
still feels full. On pointer move, only the 9 by 9 cell neighbourhood under the
cursor is redrawn one class brighter, with a 400ms decay. That local redraw must
stay under 1ms. Skip the pointer effect entirely on touch and in reduced motion.

**`<AsciiText>`** maps any string to a chosen ramp for headline treatment, and
provides the scramble decode: on reveal, each character cycles through
`!<>-_\\/[]{}=+*^?#` for 6 to 14 frames, staggered 18ms per character, then
settles. Use on every kicker and on the hero h1 once.

**`<AsciiArt>`** renders a luminance ramp `"  .:-=+*#%@"` from an SVG mask or a
signed distance field. Use it for the wordmark VOID in the hero, sized to the
character grid, animating from noise to legible over 900ms on load.

**`<AsciiBox>`** a bordered container drawn with `+ - |` characters instead of CSS
borders, corners as `+`, used for the terminal, the architecture diagram and the
ledger panel.

**`<AsciiBeam>`** animated connection lines between two DOM nodes, drawn as a
string of `-` and `=` with a `>` head that travels along the path. Speed 60 cells
per second. Used in the architecture section.

**`<AsciiSparkline>`** and **`<AsciiBars>`** monospace mini charts for inline
numbers, using `▁▂▃▄▅▆▇█` and `#`, used inside cards.

**Cursor**: replace the default cursor on pointer devices with a blinking block
caret `█` in `--accent`, 14px, that snaps to the ASCII grid (round position to the
nearest cell). It grows to a bracket pair `[  ]` around interactive elements on
hover. Fall back to the system cursor on touch and in reduced motion.

**Easter eggs**: key `G` toggles a 14px grid overlay, key `T` toggles the CRT
theme, and typing `void` anywhere dissolves the whole page into falling ASCII rain
for 1.5s and back. Announce nothing, just make it work, and disable all three in
reduced motion.

### 3.5 Motion rules

- One reveal primitive everywhere: opacity 0 to 1, `translateY(14px)` to 0,
  `filter: blur(6px)` to 0, 700ms, `--ease`, triggered at 15 percent visibility,
  `once: true`, staggered 60ms between siblings.
- Headlines use a word mask reveal: each word in an overflow hidden span, rising
  from 100 percent with 40ms stagger.
- Hero uses a load sequence: 5 steps, 90ms apart, eyebrow, h1, sub, buttons,
  figure.
- Buttons: pill, 22px radius, a light sweep gradient crossing on hover, 2px lift,
  0.97 scale on press.
- Cards: a radial spotlight following the cursor at 8 percent opacity, plus a
  1px running border light on the primary card.
- Numbers count up when they enter the viewport, with mono tabular figures so the
  layout never shifts.
- Page to page navigation uses the View Transitions API where supported.
